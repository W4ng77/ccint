# 人工标注指南（v1，草案待确认）

对应 SPEC §22–§24。标注对象是**观测单元**，分三类：种子帖、回复（深度 1 或深度 2）、引用帖。
转发没有文本，**不作为标注单元**；转发者只作为结构特征使用。

每个单元标注两个**互相独立**的维度，外加一个把握度。

## 标注时能看到什么

- **种子帖**：作者的 handle 和 displayName、帖子正文、帖子链接。
- **回复**：root 帖正文 → 父帖正文 → 当前回复正文（深度 1 的回复，父帖就是 root），外加当前作者和帖子链接。
- **引用帖**：被引用的帖子正文 → 引用帖正文，外加当前作者和帖子链接。

标注员可以点开链接查看作者主页。
标注员**看不到**任何系统判定：没有 actor 启发式类型，没有 topic，没有 feed 标记，也没有互动计数。

## 维度 A：作者的角色（`role`）

判断的是**这个作者是谁**，与这一条帖子具体在做什么无关。

| 值 | 判定要点 |
|---|---|
| `automated_feed` | 机器按模板发帖：泄露站或勒索监控 bot、CVE 播报 bot、RSS 自动转贴。特征是格式高度一致、没有第一人称、发帖频率很高 |
| `organizational_broadcast` | 机构官方号，但不是新闻媒体，例如公司、政府机构、会议、厂商、安全团队官方号。由人运营，但代表的是机构 |
| `news_media` | 新闻机构或记者的**职务**账号，发布或转述新闻报道 |
| `security_professional` | 以个人身份发言的安全从业者或研究者（从主页简介、发言内容能看出专业身份） |
| `individual_participant` | 普通个人，没有明显的专业安全身份 |
| `unclear_other` | 信息不足以判断，或者不属于上面任何一类 |

规则：
- 个人记者用个人账号闲聊，归 `individual_participant` 或 `security_professional`，**不归** `news_media`。
- 能看出是 bot，但内容是新闻转贴，归 `automated_feed`。
- 拿不准时选 `unclear_other`，**不要猜**。

## 维度 B：这一条的功能（`function`）

判断的是**这一条帖子在对话里做了什么**，与作者是谁无关。

| 值 | 判定要点 |
|---|---|
| `broadcast_or_repost` | 单向发布或转贴：新闻标题加链接、模板化告警、「转发一下」。不回应任何人，也不邀请讨论 |
| `substantive_reply` | 针对上文给出有内容的回应：补充事实、提出反驳、做出分析 |
| `information_seeking` | 提问、求证、求资源（「客户数据受影响了吗？」） |
| `information_providing` | 主动提供信息或资源：答复问题、给出链接或 IOC、说明处置方法 |
| `discussion_or_reaction` | 表达态度或情绪、简短反应、评论（「又来？」「太离谱了」） |
| `unclear` | 看了上下文仍无法判断 |

规则：
- 种子帖（root）也要标维度 B。例如「标题 + 链接」的种子帖是 `broadcast_or_repost`；种子帖本身在提问，就标 `information_seeking`。
- 一条同时符合多类时，选**主要功能**，把次要功能写在 `notes` 里。
- 回复里即使没有任何网安关键词也照常标注。它属于这个网安对话的邻域（SPEC §15），**不要**因为没提到网安就标 `unclear`。
- 纯表情或单个词，只要结合上下文能看出是反应，就标 `discussion_or_reaction`。

## 把握度（`confidence`）

填 `high`、`medium` 或 `low`。

## 流程

1. **信度子集**：两名标注员独立完成，完成前互不讨论，也不互看结果。
2. 其余单元：每条由一名标注员完成。
3. 信度子集完成后，计算原始一致率和 Cohen's κ（SPEC §26）。
   分歧的条目由两名标注员讨论裁决，裁决结果另存一列，**不覆盖**原始标注。
4. 如果 κ 偏低，先修订本指南（版本升为 v2），再继续，**不要**改已经完成的标注。
